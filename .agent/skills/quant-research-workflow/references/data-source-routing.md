# 数据源路由：PandaData 与山西证券

两条数据链路服务于不同任务，不共享认证，不作为彼此的失败兜底。优先根据用户指定的动作和来源路由；仍有歧义时先澄清，不要自行拼接数据。

## 路由表

| 用户目标 | 唯一路由 | 边界 |
|---|---|---|
| 使用专家团复现研报/论文、正式挖掘因子、平台运行、统计审计或 tearsheet | WorkBuddy 已连接的 PandaData Connector；数据任务先检查认证，再按专家团登记契约调用 | PandaData 不可用、认证失败或接口错误时阻断；不得回退到山西证券数据冒充同一研究流程 |
| 在 quant-lab 中拉取、导出、缓存历史行情/财务数据，或运行仓库自己的 `strategy` / `backtest` | `.agent/skills/shanxi-securities-tushare/` 中的既有技能和 `sxsc_tushare` 项目客户端 | 仅 T-1 历史；使用 `core.tushare_provider.TushareProvider` 的已有缓存/归一化逻辑；不切换公开版 Tushare 或 PandaData |
| 用户明确指定“山西证券”或 `sxsc_tushare` | 山西证券本地链路 | 不额外调用 PandaData，除非用户另行要求独立对照 |
| 用户明确指定 PandaData 专家团流程 | PandaData 链路 | 不以本地山西证券数据补足缺失接口或结果 |
| 两条来源都被明确要求比较 | 两个独立运行 | 分别记录来源、参数、样本、回执与结果；只有用户批准且定义好时间、股票池、复权、字段和缺失处理后，才制作明确标记的对照，不混合原始数据或冒称同口径 |

## PandaData 专家团研究

1. 将金融数据闸门设为关闭，先调用 `auth_status`。
2. 认证可用后，按已登记的 PandaData 接口契约执行最低路由；已登记接口不得先做动态检索。只有契约明确失效时，才按契约获取一次方法文档；只有方法不存在时，才进行一次接口发现。
3. 对研报/论文复现、基本面复现、量价因子和基准补充等任务，按当前专家团契约路由方法；任务命中多类时取方法并集。方法名、参数和空数据复查规则以实际加载的 PandaData 接口契约为准，不凭记忆补参数。
4. 留下每个接口的真实方法、实际参数、状态、行数、日期范围和关键字段。返回 0 行时按契约校验交易日/代码、放宽窗口、去除非必填过滤并进行真实重试；只有满足复查条件才可报告无数据。
5. 完成最低路由、空结果复查及回执核验之前，不得进行数据结论、排名或回测结论。Connector 不可用或认证失败时按宿主规则请求连接/授权或报告阻断，绝不改用本地数据静默兜底。
6. PandaAI CLI 负责平台登录、因子运行与结果收集，不等同 PandaData 数据接口；平台登录成功也不代表用户批准收费运行。

## 山西证券 quant-lab 本地链路

1. 按 `.agent/skills/shanxi-securities-tushare/SKILL.md` 执行环境检查；缺少 `SXSC_TUSHARE_TOKEN` 时停止，不取数。
2. 使用项目既有 `sxsc_tushare`、`core.tushare_provider.TushareProvider` 和缓存；不另造客户端/缓存，不把 `TUSHARE_TOKEN` 当作 `SXSC_TUSHARE_TOKEN`。
3. 只请求网关支持的 T-1 历史数据。接口以该技能的 `api-index.md` 为准；未知接口先查该技能指定的券商文档，不凭模型记忆猜测。
4. 权限错误按原样报告，不自动换 token 或来源重试。空表先核对日期、交易日、股票代码与参数，不把异常或权限问题说成“无数据”。
5. 运行本地策略/回测时标注来源、数据窗口、复权口径、成交假设与成本；回测读取本次产生的真实 equity/trade 产物。不得把 pandas 测试夹具、缓存样例或仅有因子值的文件当作有效回测收益。

## 禁止事项

- 禁止把 PandaData 数据和山西证券数据拼成一个未经说明的因子面板或收益序列。
- 禁止在一条链路认证失败后使用另一条链路隐藏失败。
- 禁止复制、回显或提交任何数据源令牌、账号配置或平台登录信息。
- 禁止把数据覆盖差异省略；跨源对照必须逐来源报告接口、样本、日期范围、单位、复权与缺失处理。
